Six months ago, most of us wouldn't have had a great answer. Today, there's a model built exactly for this: ColPali.
 
𝗤: 𝗪𝗵𝗮𝘁 𝗶𝘀 𝗖𝗼𝗹𝗣𝗮𝗹𝗶? ColPali (Contextualized Late Interaction over PaliGemma) is a vision-language retrieval model that embeds an entire document page — text, tables, charts, layout, everything — directly as an image. No text extraction. No chunking. No layout parser. It indexes the page the way a human would actually look at it.
 
𝗤: 𝗛𝗼𝘄 𝗶𝘀 𝘁𝗵𝗶𝘀 𝗱𝗶𝗳𝗳𝗲𝗿𝗲𝗻𝘁 𝗳𝗿𝗼𝗺 𝘁𝗿𝗮𝗱𝗶𝘁𝗶𝗼𝗻𝗮𝗹 𝗢𝗖𝗥? Traditional OCR (covered in my last post) is a multi-stage pipeline: pre-process → segment → extract features → classify characters → post-process — then hand the extracted text to a separate retrieval system. Every one of those stages is a place where a table structure, a chart, or a stamp can get lost or garbled.
 
ColPali skips all of it. A single vision-language model encodes the page into patch-level embeddings, and a "late interaction" mechanism (borrowed from ColBERT) matches each query word against the most relevant patches of the page directly — no intermediate text representation at all.
 
𝗤: 𝗪𝗵𝗮𝘁 𝗮𝗿𝗲 𝘁𝗵𝗲 𝗮𝗱𝘃𝗮𝗻𝘁𝗮𝗴𝗲𝘀? → Understands tables, charts, and figures natively — not just running text → No brittle OCR/parsing pipeline to maintain → Much faster to index than OCR + layout analysis + chunking → Retrieval is interpretable — you can visualize exactly which patch of the page matched the query
 
𝗤: 𝗪𝗵𝗲𝗿𝗲 𝗰𝗮𝗻 𝘄𝗲 𝘂𝘀𝗲 𝗶𝘁? → RAG over visually complex PDFs (financial reports, scientific papers, legal contracts) → Enterprise search across scanned/mixed-format document archives → Multilingual document retrieval without language-specific OCR tuning → Any pipeline where "OCR then embed the text" keeps losing visual context
 
And ColPali isn't alone — it's spawned a whole family: ColQwen2/2.5 (stronger Qwen-VL backbone), ColQwen3 and ColQwen-Omni (text + visual in one model), ColSmol and ColModernVBERT (lightweight, efficient versions for production), among others.
